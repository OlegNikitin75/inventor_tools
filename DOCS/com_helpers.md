# `com_helpers.py`

Обёртки над COM-коллекциями Inventor: убирают 1-индексацию и защищают
от падений на «капризных» свойствах.

---

## 🎯 Зачем нужен этот модуль

Когда Python работает с Inventor через COM, он получает **коллекции** —
параметры, компоненты сборки, свойства, виды на чертеже. Все они устроены
одинаково:

- есть `Count` — сколько элементов;
- есть `Item(i)` — получить элемент по номеру.

Но есть три неудобства:

1. **Индексация с 1, а не с 0.** В обычном Python список начинается с `[0]`,
   в Inventor — с `Item(1)`. Забыть легко, и код молча даст неверный
   результат.
2. **Нужно писать `range(1, Count + 1)`.** Если забыть `+1`, последний
   элемент просто не обработается. Классическая ошибка, которую трудно
   заметить.
3. **Это повторяется в каждом скрипте.** Каждый раз, когда нужно пройти
   по параметрам, компонентам или свойствам, пишется один и тот же цикл.

Модуль прячет эту возню в две маленькие функции, чтобы в остальном коде
вы писали просто и понятно.

---

## 📦 API

### `iterate_collection(collection)`

Генератор по COM-коллекции с 1-индексацией.

| Параметр     | Тип                     | Описание                                |
| ------------ | ----------------------- | --------------------------------------- |
| `collection` | COM-коллекция \| `None` | Объект с атрибутами `Count` и `Item(i)` |

**Возвращает:** элементы по одному, от `Item(1)` до `Item(Count)`.
Если `collection is None` — пустой генератор.

**Пример:**

```python
from com_helpers import iterate_collection

for param in iterate_collection(doc.ComponentDefinition.Parameters):
    print(param.Name)
```

**Почему генератор, а не список:** для сборки из 5000 компонентов список
занял бы много памяти, генератор — нет.

---

### `safe_get(obj, name, default=None)`

Безопасное чтение свойства — как `getattr`, но не падает.

| Параметр  | Тип             | Описание                                           |
| --------- | --------------- | -------------------------------------------------- |
| `obj`     | `object`        | Любой объект (обычно COM-объект Inventor)          |
| `name`    | `str`           | Имя свойства, например `"Value"` или `"Thumbnail"` |
| `default` | `Any`, optional | Что вернуть при ошибке. По умолчанию `None`        |

**Возвращает:** значение свойства или `default`, если `getattr` бросил
исключение.

**Пример:**

```python
from com_helpers import safe_get

value = safe_get(prop, "Value", default=0.0)
```

**Зачем:** COM иногда бросает исключение на пустых свойствах (видели на
`Thumbnail` в iProperties). Без обёртки — падение программы, с обёрткой —
`default`.

## 📖 Разбор по строкам

### `iterate_collection`

```python
def iterate_collection(collection):
    """Обёртки над COM-коллекциями Inventor."""
```

Объявляем функцию `iterate_collection`, которая принимает один аргумент —
`collection` (коллекция Inventor).

```python
    if collection is None:
        return
```

Если коллекции нет (например, у документа без параметров `Parameters`
может быть `None`), сразу выходим. Без этой проверки следующая строка
`collection.Count` упала бы с ошибкой
`AttributeError: 'NoneType' object has no attribute 'Count'`.

```python
    for i in range(1, collection.Count + 1):
```

Цикл от 1 до `Count` включительно. Именно `+1`, потому что `range(1, 4)`
даёт `1, 2, 3` — правая граница не включается. Если бы написали
`range(1, Count)`, последний элемент коллекции потерялся бы.

```python
        yield collection.Item(i)
```

Ключевое слово `yield` делает функцию генератором. Это значит:

- функция не выполняется сразу целиком;
- она выдаёт по одному элементу за раз, когда её перебирают в цикле `for`;
- память не тратится на создание всего списка сразу.

Для коллекции из 5000 компонентов сборки это важно: список из 5000
объектов занял бы много памяти, а генератор — нет.

### `safe_get`

```python
def safe_get(obj, name, default=None):
```

Вторая функция. Принимает объект, имя свойства и значение по умолчанию.

```python
    try:
        return getattr(obj, name)
```

`getattr(obj, name)` — это то же самое, что `obj.name`, но имя передаётся
строкой. Например, `safe_get(prop, "Value")` вернёт то же, что
`prop.Value`.

Зачем так, а не напрямую: чтобы можно было перехватить ошибку. Мы видели
её на `Thumbnail` в iProperties — COM иногда бросает исключение на пустых
свойствах.

```python
    except Exception:
        return default
```

Если `getattr` упал — не обрушиваем программу, а возвращаем `default`
(по умолчанию `None`). Это спасает от падений на «капризных» свойствах.

---

## 💡 Пример использования целиком

```python
from com_helpers import iterate_collection, safe_get

def dump_parameters(doc):
    """Печатает имя и значение всех параметров документа."""
    params = doc.ComponentDefinition.Parameters
    for p in iterate_collection(params):
        name = safe_get(p, "Name", default="<без имени>")
        value = safe_get(p, "Value", default="<нет значения>")
        print(f"{name} = {value}")
```

## ✅ Что даёт модуль

- **Меньше шума** — в скриптах нет `range(1, Count + 1)`.
- **Меньше ошибок** — нельзя забыть `+1` или перепутать индексацию.
- **Устойчивость** — «капризные» COM-свойства не роняют программу.
- **Экономия памяти** — генератор вместо списка.
